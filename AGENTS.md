# Documentation contributor guide

This repository documents pdfmake **0.3.x**. The `0.1` branch owns the older
0.1/0.2 docs. Keep public page paths stable, including the historical spelling
`document-medatadata`; add aliases if introducing new paths.

Author content in `content/` with TOML title, description and weight. Prefer a
complete runnable example before options and edge cases. Explain environment,
minimum version, defaults, units and failure behavior. Use Promise-based output
methods. Resource policies must be synchronous. Distinguish PDF encryption from
server resource-access controls. Preserve security caveats and advanced features.

`npm ci`, `npm run docs:generate`, `npm test`, `npm run build` validate the corpus,
executable examples, MCP protocol and all generated internal links. Install Hugo
0.168.0 for the website. The first build step generates versioned Markdown,
`llms.txt`, `llms-full.txt` and `docs-index.json` from the same pages. Do not edit
these generated files manually. The MCP stdio server in `mcp/server.mjs` reads
that snapshot; it must not execute example code or fetch remote content.

`layouts/` and `static/assets/` own the documentation UI. The historical theme
is retained for reference but is not loaded. Keep the site usable without JS;
JS adds search and copy buttons. Use semantic HTML and local assets. Docs tooling
requires Node >=24.11; this is separate from the library's Node >=20 runtime.

Translations use language-suffixed Markdown files (`.de.md`, `.fr.md`, `.es.md`,
`.pt-br.md`) beside the English original. Preserve code/API identifiers and include
`sourceDigest`, the SHA-256 of the English source with LF line endings, after
reviewing changes. Do not copy untranslated English pages into language URLs or
claim them in hreflang. Missing translations link explicitly to English or the
locale start page. Search/MCP/Markdown exports must retain language separation.

All supported languages must cover the full English page set. Translation checks
compare source digests, fenced code, runnable examples, heading structure, table
rows and localized internal links. Translate explanatory prose fully; do not
replace reference sections with summaries. Keep shared example source/output
unchanged so every language demonstrates the same tested API behavior.

Chapter navigation is curated by task in `data/navigation.json`, not inferred from
the content directory. Keep all existing page URLs reachable. The primary
playground is a rendered documentation route, mounted directly into the shared
shell. Preserve its editor state across SPA navigation and cancel background work
when detached. Use `standalone.html` only for isolated previews and library-only
development. Validate navigation, state retention, Back/Forward, mobile drawer,
themes and language equivalents with the browser suite when changing this shell.

Versions are configured in `versions.json`. Use the npm Hugo wrapper; do not edit
`.generated/` or hardcode another series in templates, exporters or MCP. Never
advertise a future release without a real verified snapshot. Keep playground
runtime pins aligned and version-switch chapter metadata explicit. Test current
and synthetic future corpus paths without publishing fake releases.

Code example variants are generated by `scripts/code-examples.mjs`. Never maintain
independent manually diverging JS/TS copies. Include all variants in portable
Markdown. New document examples must pass the browser TypeScript checker; avoid
`any`, suppression comments or unchecked type assertions to conceal errors. Keep
inline editors isolated, cancel workers on navigation and preserve independent
language drafts. Environment-dependent examples must not pretend to execute Node
or access private files in browser previews.
